# Крафт скинов

Реализация согласованной первой версии из [исследования](crafting-research.md).

## Правила

- `/craft`, пункт «Крафт» между кейсами и рейтингом. Обычный веб и Mini App используют
  существующую сессию CaseGo. Гость получает ссылку на вход на странице кейсов.
- Ровно 10 доступных экземпляров одинаковой редкости: Mil-Spec → Restricted →
  Classified → Covert. Разрешены разные поддерживаемые коллекции и одинаковые виды,
  но не повтор одного UUID. Covert, ножи и неизвестные предметы не подходят.
- Версия `craft-10-v1`: выбираем равновероятно один из 10 входов, затем один результат
  следующего уровня его коллекции. Предпросмотр показывает `n / 10 / m` для каждого
  исхода. Это модель CaseGo, не официальные вероятности Valve. Float, StatTrak,
  Souvenir, цены, ножевые контракты и реальные предметы Steam не моделируются.
- «Коллекция» фильтрует список, не сбрасывая выбранные входы из других коллекций.
  Изменение редкости очищает выбор. Автоподбор добавляет только подходящие по фильтрам
  дубликаты и не выбирает последнюю доступную копию вида автоматически.
- Перед списанием показываются исходы и проценты, предупреждение о последних копиях
  и обязательное подтверждение расходования. Потраченные копии недоступны повторно.
- Альбом — все когда-либо полученные виды; рейтинг учитывает уникальные виды из
  открытий и крафта. Расход не отнимает прогресс. «Всего»/дубликаты в коллекции —
  активные копии. История открытий остаётся историей кейсов, история крафта отдельно.
- Крафт не меняет лимит/счётчик открытий; стоимость — входные экземпляры. Результат
  можно использовать в следующем контракте, если его редкость подходит.
- История показывает последние 30 контрактов со списками входов, результатом и датой.

## Хранение и защита

Миграция `007-crafting` добавляет журнал `crafts`, nullable источник `craft_id` и
признак расходования у экземпляров. Источник ровно один: открытие или крафт.
Старые строки не переписываются и не удаляются. Потраченные экземпляры сохраняются
для альбома/аудита; `getCollection` возвращает историю получений с `consumedAt` и `source`.

Server Action берёт владельца из сессии. Под блокировкой пользователя сервер
проверяет количество, UUID, доступность, владение и канонический каталог, затем
в одной транзакции пишет контракт, расходует входы и выдаёт экземпляр. Та же блокировка
используется открытием кейсов. Ошибка выдачи откатывает и контракт, и списание.
Сочетание `(user_id, request_id)` уникально: точный повтор возвращает сохранённый
результат, иной набор с тем же ID отклоняется. Порядок входов не меняет контракт.

При неопределённом сетевом результате выбор блокируется, а «Проверить результат»
повторяет исходный requestId. После перезагрузки состояние проверяется через серверный
инвентарь и историю. Уже потраченные UUID не могут стать новым контрактом.

Аккаунт и история кешируются TanStack Query в памяти вкладки. Успешный крафт обновляет
их и инвалидирует рейтинг. Смена сессии сбрасывает все личные данные и локальный выбор;
ответ старой сессии не может записаться в кеш. Для загрузки предусмотрены скелетоны,
для результата — короткая анимация с учётом reduced-motion. Картинки используют общий
оптимизатор/HTTP-кеш. При устаревшем инвентаре сервер отказывает безопасно.

## Публикация

Перед запуском этой версии на целевой БД выполнить `bun run db:migrate`.
Если production Build Command Vercel уже выполняет эту команду, он применит `007-crafting`
автоматически. Миграции сохраняют отметки о выполнении; повторный запуск безопасен.
Проверки разработки выполнялись на отдельной локальной `cases_test`, не в рабочей Neon.

## Проверки

`TEST_PG_SOCKET=... bun run test` покрывает вероятности, несовместимые входы, чужие UUID,
повторы, rollback при ошибке вставки результата, гонки между соединениями, постоянство
альбома/рейтинга и повторное использование полученного крафтом предмета.

На локальном сервере с `DATABASE_URL`, указывающим на ту же `cases_test`:

```sh
CASE_TEST_BASE_URL=http://127.0.0.1:3099 TEST_PG_SOCKET=/path/to/.s.PGSQL.55439 bun run test:craft
CASE_TEST_BROWSER=webkit CASE_TEST_BASE_URL=http://127.0.0.1:3099 TEST_PG_SOCKET=/path/to/.s.PGSQL.55439 bun run test:craft
```

Браузерный тест создаёт только собственный аккаунт, проверяет гостя, выбор, вероятности,
подтверждение, результат, альбом/рейтинг/лимит, reload, потерю ответа уже выполненного
контракта, безопасный повтор и выход в другой вкладке. Проверяет ширины 320/390/1280
в светлой и тёмной темах; удаляет свой аккаунт после проверки.
