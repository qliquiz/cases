# Тестовый рейтинг игроков

## Правила первой версии

- Отдельная страница `/leaderboard` в том же Next.js-приложении. Навигация «Кейсы / Рейтинг», обе темы и мобильная ширина.
- Публичный топ-50 доступен гостям. Для участия нужно войти на странице кейсов и явно сохранить публичный ник.
  Старые аккаунты не публикуются автоматически; имя, email, Telegram ID и внутренний UUID не попадают в публичный ответ.
- Участник получает место после первого сохранённого открытия. Публичный ник уникален без учёта регистра:
  3–24 символа, латинские/русские буквы, цифры, пробел, `_`, `-`; хотя бы одна буква, без пробелов по краям.
- Очки — число различных `item_id` во всех сохранённых открытиях аккаунта. Общий предмет из двух кейсов считается один раз.
  Повтор запроса UUID, дубликат и сброс лимита не добавляют уникальных предметов. Исторические предметы вне текущего каталога тоже учитываются.
- Место определяется только очками: при равенстве места общие (1, 1, 3). Внутри равного места порядок по нику.
  В топе максимум 50 игроков, даже если на границе равенство.
- Показываются число открытий и число выпадений редких особых предметов, включая повторы. Редкие распознаются по ID
  редких пулов текущего каталога. Если кейсы когда-нибудь удаляются из каталога, потребуется сохранить классификацию их редких предметов.
- «Моё место» видно и за пределами топ-50. До публикации показывается собственная статистика без места.
- Смена ника не сбрасывает статистику. «Скрыться из рейтинга» убирает публичный ник и запись из топа, но не удаляет коллекцию;
  повторное участие использует всю накопленную историю. Ник после скрытия освобождается.
- Рейтинг явно тестовый: пока сброс лимита не ограничен, результаты зависят от числа открытий. Сезонов, наград и цен нет.
  Настоящий сезон с отдельным зачётом требует следующего решения; текущую коллекцию автоматически не обнуляем.

## Реализация и публикация

`006-leaderboard` добавляет nullable `app_users.public_nickname` и уникальный индекс, не копируя данные из авторизации.
Перед запуском новой версии выполнить `bun run db:migrate` для нужной БД (либо использовать настроенную production-команду Vercel).
Миграция проверена на отдельной локальной `cases_test`; рабочая Neon этим заданием не изменяется.

Один SQL-запрос даёт согласованные топ, собственное место и число участников; клиент получает только разрешённые поля,
а не сырые строки пользователей. Server Action изменения ника каждый раз проверяет сессию и берёт user ID только из неё.
Публичные и персональные данные не складываются в общий кеш. Обновление — при загрузке страницы или по кнопке, без polling.

Ники — пользовательский текст с ограниченным алфавитом, React экранирует вывод. Это не система модерации;
перед широким публичным продвижением отдельно нужны правила ников/жалобы и защита от автоматического накручивания.

## Проверка

`TEST_PG_SOCKET=... bun run test` проверяет подсчёт, равенства, повторы, редкие предметы, приватность, скрытие,
валидацию/уникальность ника и собственное место №51 за пределами топа. SQL-тест рейтинга использует отдельную временную схему.

После запуска локального dev-сервера с `DATABASE_URL`, указывающим именно на `cases_test`:

```sh
CASE_TEST_BASE_URL=http://127.0.0.1:3098 TEST_PG_SOCKET=/path/to/.s.PGSQL.55439 bun run test:leaderboard
CASE_TEST_BASE_URL=http://127.0.0.1:3098 TEST_PG_SOCKET=/path/to/.s.PGSQL.55439 CASE_TEST_BROWSER=webkit bun run test:leaderboard
```

Стенд создаёт только свои тестовые аккаунты и удаляет их после проверки. Проверяются гостевой просмотр,
публикация, занятый ник, сохранение после reload, обновление, отказ без сессии, скрытие, навигация и обе темы на 320/390/1280 px.
