# Бот CaseGo: /start и запуск Mini App

Бот работает в этом же Next.js-проекте на Vercel. Отдельный сервер, long polling, n8n и новые миграции не нужны.
`POST /api/telegram/webhook` отвечает на `/start` в личном чате приветствием и кнопкой **Открыть CaseGo**.
Команды из групп, правки сообщений и сообщения других ботов игнорируются.

## Подключение после деплоя

1. В Vercel → проект → Settings → Environment Variables задайте для **Production**:
    - `APP_ORIGIN=https://case2go.vercel.app`
    - `TELEGRAM_BOT_TOKEN` — токен нужного бота из BotFather.
    - `TELEGRAM_WEBHOOK_SECRET` — отдельный случайный секрет. Сгенерируйте локально: `openssl rand -hex 32`.
      Не используйте токен бота или OIDC client secret вместо него. Не присылайте секреты в чат.
2. Задеплойте код с webhook-обработчиком. Production-адрес должен быть доступен Telegram без Vercel login/Deployment
   Protection. Не регистрируйте Preview-деплой как webhook рабочего бота.
3. В корне локального проекта, уже привязанного через `vercel link` к нужному существующему проекту:

    ```bash
    bunx vercel@latest env run -e production -- bun run bot:check
    ```

    Сверьте `bot` с username нужного бота. Команда только читает настройки Telegram и не проверяет доступность сайта.
    Токен и URL существующего webhook не выводятся.

4. Подключите webhook и постоянную кнопку меню:

    ```bash
    bunx vercel@latest env run -e production -- bun run bot:setup --apply
    ```

    Это **изменяет настройки живого бота**. Сначала выполняется авторизованный no-op запрос к обработчику, без сообщения
    пользователю. При неверном секрете, отсутствующем маршруте, редиректе или закрытом деплое регистрация не выполняется.
    Затем устанавливаются webhook и кнопка меню. Сообщения, ожидающие обработки, не удаляются.

    Если у старого бота уже есть webhook другого проекта, скрипт остановится. Только если старое приложение больше не
    должно получать команды, повторите с дополнительным `--replace-webhook`. Это отключит его от получения новых updates.

5. Отправьте боту **новое** `/start`, получите приветствие, нажмите «Открыть CaseGo». Проверьте вход и открытие кейса.
   При необходимости снова выполните `bot:check`: `webhookConfigured` и `menuConfigured` должны быть `true`.

Если переменные уже безопасно заданы в `.env.local`, можно выполнить `bun run bot:check` и `bun run bot:setup --apply`
напрямую. Не направляйте локальные тесты на рабочего бота. Тесты проекта используют только искусственные данные и mock fetch.

## Важные отличия и ограничения

- `TELEGRAM_BOT_TOKEN` нужен для Mini App auth и настройки бота; сам по себе он не включает приём команд.
- `TELEGRAM_WEBHOOK_SECRET` проверяет источник webhook, сравнивается в constant time. Без корректной конфигурации маршрут
  закрыт. Тела ограничены 64 KiB; секреты и входящие сообщения не логируются.
- Ответ использует штатный Bot API метод `sendMessage` прямо в JSON-ответе webhook. Telegram выполняет его сам;
  отдельного сетевого запроса из Vercel не требуется. При этом API не возвращает приложению результат отправки сообщения.
  Финальное подтверждение — полученное приветствие в Telegram, а не только `bot:check`.
- Доставка updates не гарантирует exactly-once: при повторе webhook может появиться повторное приветствие. Это не
  создаёт аккаунт, не открывает кейс и не меняет лимиты/коллекцию. Учётные данные подтверждаются только при входе Mini App.
- `lastDeliveryErrorAt` в `bot:check` — время последней известной ошибки Telegram, в том числе исторической; статус не
  доказывает успешную отправку приветствия. Если очередь `pendingUpdates` растёт — проверьте логи Vercel и конфигурацию.
- Если установка меню завершится ошибкой после установки webhook, предыдущий успешный шаг не откатывается. Исправьте
  причину и повторите setup: целевые настройки останутся теми же, очередь не удаляется.
- Регистрация webhook **не запускается при каждом build/deploy**. Для того же домена и секрета достаточно одного раза;
  при смене адреса/секрета повторите setup после деплоя. Остановите прежний polling-процесс, если он ещё работает.
- Main Mini App в профиле бота и веб-вход OIDC — отдельные настройки BotFather; setup настраивает только webhook и меню.
- Если `/start` вообще не уходит из клиента Telegram, это отдельная проблема отправки, которую обработчик не исправляет.

## Источники решения

Проверено 26 сентября 2026 года по официальной документации:

- [Получение updates и setWebhook](https://core.telegram.org/bots/api#setwebhook): HTTPS POST, повтор при не-2xx,
  заголовок `X-Telegram-Bot-Api-Secret-Token`, `allowed_updates`, сохранение очереди.
- [Ответ методом Bot API внутри webhook](https://core.telegram.org/bots/api#making-requests-when-getting-updates):
  JSON с полем `method`, без подтверждения результата метода.
- [InlineKeyboardButton](https://core.telegram.org/bots/api#inlinekeyboardbutton): `web_app` доступен в личном чате.
- [Кнопка меню Mini App](https://core.telegram.org/bots/webapps#launching-mini-apps-from-the-menu-button):
  настройка через `setChatMenuButton` или BotFather.

Решение проекта: небольшой stateless webhook для приветствия; хранение учётных данных и игровые операции остаются
в существующей серверной части. Next.js Route Handlers проверены по локальному
`node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/route.md`.
